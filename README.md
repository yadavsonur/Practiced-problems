# DSA Practice — Java Solutions

A structured collection of Data Structures and Algorithms problems practiced across platforms such as GeeksforGeeks, Take U Forward, and LeetCode.

The goal of this repository is to make interview preparation easier: each problem will include a clean Java implementation and a concise revision sheet that helps recall the key idea quickly.

## Repository structure

Each topic has its own folder. Each problem gets a dedicated folder containing two files:

```text
Problems-solved/
├── Arrays/
│   └── Two-Sum/
│       ├── TwoSum.java
│       └── TwoSum.md
├── Linked-List/
│   └── Reverse-Linked-List/
│       ├── ReverseLinkedList.java
│       └── ReverseLinkedList.md
└── ...
```

*The examples above illustrate the intended structure; folders will appear as problems are added.*

## What each problem contains

### `ProblemName.java`
- A readable, efficient Java solution.
- Comments for important or non-obvious steps.
- Time and auxiliary-space complexity.

### `ProblemName.md`
A quick-revision cheat sheet with:
- **Recognition trigger:** clues that suggest this pattern.
- **Core intuition:** the main observation in plain language.
- **Algorithm:** the essential steps.
- **Complexity:** time and space.
- **Edge cases and pitfalls:** mistakes to avoid.
- **Pattern / invariant:** the reusable idea to remember.
- **Dry run:** included when it meaningfully clarifies the logic.

## How to use this repository

1. **Practice first:** attempt the problem before opening the solution.
2. **Understand, don't memorize:** read the intuition and identify why the approach works.
3. **Recall actively:** try to reproduce the algorithm without looking.
4. **Revise by pattern:** use the cheat sheets to connect related problems.
5. **Revisit weak areas:** return to problems whose approach or edge cases are hard to recall.

## Progress and accuracy

This repository is a growing record of practice. Problems are added progressively, and each implementation should be checked against the problem's requirements and edge cases. Platform-specific input/output formats may differ, so adapt the Java code when submitting to a particular judge.
